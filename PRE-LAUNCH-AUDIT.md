# Предзапусковой аудит NOVA

Аудит по [Issue #79](https://github.com/blacklivi/nova-lounge-website/issues/79). Базовая версия `main` — `160d6e67b59d0b068128cbbc3a4e3d279e4b4ab0`. Изменения и тесты подготовлены в `codex/pre-launch-audit-79`. Решение по запуску — [NO-GO](LAUNCH-DECISION.md).

## 1. Бронирования и доступ сотрудников

- Бронирования пройдены через браузер с главной, HÓF, Победителей и Востока. Для каждого сценария после ответа 201 и появления подтверждения проверена запись в локальной D1 с нужным заведением и временем.
- В API проверены все четыре кода +375, нормализация номера, неполная маска и недопустимый код, границы 1/16 гостей, отсутствующее согласие, прошлые даты, несуществующая дата и шаг 15 минут. Эмуляция браузера работала в часовом поясе Лос-Анджелеса, а минимальная дата формы сверялась с Минском. Отдельно прогнаны существующие тесты валидатора с фиксированными датами.
- Повтор в другом формате номера и три параллельных одинаковых запроса оставили по одной записи. Проверены honeypot без записи, 400, 403, 413, 429 и повтор из формы после прерванного запроса. Проверка искусственного сбоя D1 с ответом 500 и отдельный тест вставки номера из буфера обмена остаются открытыми.
- В D1 созданы синтетические manager и viewer. Проверены вход owner, manager, viewer, общий и отфильтрованный подсчёт, запрет чужого фильтра и чужого ID, запрет изменения viewer, запрет доступа manager к списку сотрудников, отзыв и истечение сессий. Проверены атрибуты Secure, HttpOnly, SameSite=Strict и отказ API без сессии. Отдельных GET API для карточки и истории нет. Карточка использует данные разрешённого списка, история сверялась непосредственно в локальной D1.
- В мобильном интерфейсе проверены вход owner, карточка, телефонная ссылка, комментарий, смена статуса, история и выход. В API проверены повтор статуса без второй записи в истории и согласованность истории при одновременных изменениях.
- Обзор кода выявил параметризованные запросы к персональным данным, ограничение области доступа на сервере и no-store на ответах бронирований. Убедились, что публичный успешный ответ не содержит персональных данных. Полный аудит хранения, удаления и журналирования на реальном Worker не проведён.

## 2. Админка и контент

- В браузере выполнены вход, редактирование RU/EN, публикация и проверка обеих версий в гостевой странице. Проверка текста использовала DOM, поскольку действующая вёрстка скрывает этот элемент. В API проверены 401 без сессии, защита при записи, запрет небезопасной ссылки и сохранение HTTPS-ссылки.
- Локальная R2 приняла WebP из репозитория. Публичный URL вернул исходные байты и правильный Content-Type. Поддельная сигнатура отклонена. В локальной D1 сохранены ссылка на фото и параметры кадрирования. Интерактивная обрезка, клиентское сжатие и удаление загруженного объекта не пройдены в браузере.
- Проверены создание черновика события, его отсутствие в публичном API, публикация, появление в HTML выбранной афиши и повторное скрытие. Некорректная календарная дата теперь возвращает 400. Автоматический перевод Workers AI и фактический контент опубликованного демо не проверены. Тексты CMS публикуются сразу, отдельный серверный черновик для них в текущем интерфейсе не проверялся.

## 4. SEO, скорость и релиз

- Проверены восемь публичных URL на локальном Worker: главная, три заведения и четыре страницы афиши. На всех проверены 200, canonical, описание, JSON-LD и HTML для обходчика. Проверены favicon, JS, базовый контент, 404 на отсутствующем маршруте/API/фото и заголовки /reserved.
- Правила robots и sitemap для workers.dev и nova-lounge.by проверены локально вызовом SEO-маршрута с соответствующим URL. Демо закрыто для обхода, sitemap отсутствует. Для официального имени ожидается sitemap с восемью URL. Live HTTPS, фактическая индексация, содержание внешних страниц меню, карт и соцсетей не подтверждены. Прокси отклонил соединение с workers.dev, прямой запрос не разрешил имя, облачный браузер не запустился.
- Локальный Chromium, по одному холодному контексту на маршрут при 390 и 1440 px. На главной TTFB 21–97 мс, событие load 236–288 мс, ресурсы того же источника около 158 КиБ. HÓF — 19–22 мс, 198–216 мс, 158–160 КиБ. Афиша — 27–47 мс, 216–243 мс, 66 КиБ. В этих прогонах HTTP-ошибок ресурсов того же источника не наблюдалось. Ленивые ресурсы ниже экрана, полевые Core Web Vitals и производительность Cloudflare этими измерениями не охвачены.
- Конфигурация содержит отдельные preview D1/R2. Тестовый стенд создаёт собственные локальные привязки и применяет все пять миграций. Состояние реальных миграций, секретов, резервных копий и отката Cloudflare по этой проверке не установлено. Production и доменные настройки не изменялись.

## Подтверждённые дефекты и открытые риски

| Приоритет | Наблюдение | Статус |
| --- | --- | --- |
| P1 | Два параллельных PATCH могли создать несовместимые записи истории, если второй UPDATE ничего не изменил | Исправлено. История записывается только после успешного UPDATE в той же транзакции. Конфликт возвращает 409 с сообщением в интерфейсе. [Реализация](src/reservations.js#L108) |
| P1 | Повтор бронирования ранее выполнял проверку и вставку отдельными запросами, оставляя окно для гонки | Проверка и вставка объединены в один SQL-запрос. В исходном локальном прогоне параллельный дубль не воспроизвёлся. После правки тест подтверждает одну запись. [Реализация](src/reservations.js#L63) |
| P2 | Некорректный JSON бронирования воспроизводимо возвращал 500 | Исправлено на 400 для гостевой отправки и смены статуса. Сохранён 413 для слишком большого тела с Content-Length. [Реализация](src/reservations.js#L63) |
| P2 | CMS сохраняла событие на 30 февраля | Исправлено календарной валидацией при создании и редактировании. [Реализация](src/index.js#L56) |
| P1 | Работоспособность развёрнутого Worker и реальные настройки D1/R2 не подтверждены | Открыто. Повторить сквозной тест в выделенном preview и безопасную проверку доступа на целевом окружении |
| P1 | Telegram не подключён согласно Issue #79 и README | Открыто. До запуска проверить, что сотрудники видят и обрабатывают заявки в /reserved вручную |
| P1 | iOS WebKit и открытая экранная клавиатура | Открыто. Проверить WebKit в CI и повторить на физическом iPhone |
