# NOVA — автоматическая оптимизация изображений при загрузке

Все три существующих интерфейса админки используют один модуль `public/image-upload.js`:

1. **Редактор страниц:** заглавные фотографии, карточки заведений, галереи, изображения блоков.
2. **Старый редактор:** все поля загрузки фотографий.
3. **События и афиши:** загрузка афиш мероприятий.

## Порядок обработки

1. Выбрать файл в админке. Поддерживаются JPEG, PNG, WebP, AVIF, а также HEIC/HEIF, если браузер умеет их декодировать. Максимальный размер исходного файла — 80 МБ.
2. Браузер считывает изображение, сохраняет исходные пропорции и ориентацию, уменьшает разрешение **без увеличения** маленьких фотографий.
3. Браузер конвертирует результат в WebP с адаптивной настройкой качества. При необходимости ещё немного уменьшает разрешение, пока не получит целевой вес.
4. В интерфейсе отображается сжатый WebP и сравнение разрешения и размера до/после.
5. Только при сохранении/публикации в Cloudflare R2 отправляется **готовый WebP**. В Cloudflare D1 сохраняется путь к нему. Исходный тяжёлый файл на сервер не отправляется.
6. При новом файле создаётся новый уникальный URL. Для загруженных WebP включено длительное кеширование `Cache-Control: public, max-age=31536000, immutable`.

## Профили качества

| Назначение | Максимальная длинная сторона | Целевой размер |
|---|---:|---:|
| Заглавные фотографии NOVA и заведений, бронирование | 2400 px | 1,3 МБ |
| Карточки заведений на главной | 1400 px | 500 КБ |
| Галереи заведений | 1800 px | 850 КБ |
| Афиши | 1400 px | 500 КБ |
| Прочие изображения/фото-логотипы | 2000 px | 1 МБ |

Размеры **целевые**, а не строго гарантированные для каждого исходника. Алгоритм снижает качество и разрешение, если фото очень детальное. Серверное ограничение на уже сжатый файл по-прежнему составляет 8 МБ.

### Проверенный сценарий

Синтетический JPEG **6000×4000, 22 001 375 байт** → WebP **2400×1600, 1 224 304 байта**, уменьшение на **94%**. Также проверены ограничения карточек и афиш, передача MIME `image/webp` и сохранение адреса файла через обе редакторские формы и форму события с тестовыми API-ответами.

## Обратимость

Старые изображения в R2 не перекодируются и не удаляются. Обновление касается **новых загрузок**. В случае необходимости код можно откатить отдельным коммитом, не изменяя уже опубликованные фото и записи D1.

## Особенности

- Старые браузеры, не умеющие кодировать WebP, получают явную ошибку вместо отправки PNG/JPEG без сжатия.
- HEIC/HEIF поддерживаются лишь в браузерах, которые умеют их открыть. В остальных случаях админка рекомендует экспортировать исходник в JPEG.
- Прозрачность PNG сохраняется в WebP; внешний вид может немного отличаться из-за сжатия с потерями.
- Для пиксельных логотипов и фотографий с мелким текстом WebP может быть менее подходящим; официальные векторные SVG HÓF остаются доступными по прежним путям.
