# NOVA — сайт сети кафе, Минск

Отдельный проект `blacklivi/nova-lounge-website` → Cloudflare Worker `nova-lounge-demo`.

## Ссылки
- Сайт: https://nova-lounge-demo.blacklivi-olx.workers.dev/
- События: https://nova-lounge-demo.blacklivi-olx.workers.dev/events
- Редактор: https://nova-lounge-demo.blacklivi-olx.workers.dev/admin

## Архитектура
- `public/` — адаптивный интерфейс, события, редактор и статические фотографии;
- `src/index.js` — защищённый API редактора, загрузка изображений;
- `D1 DB` `nova-content-db` — текстовые поля и анонсы;
- `R2 MEDIA` `nova-website-media` — загруженные изображения;
- `ADMIN_PASSWORD`, `ADMIN_SIGNING_KEY` — только Cloudflare Secrets, **не хранить в Git**.

Редактирование текстов и событий в `/admin` применяется сразу, без GitHub deploy. Изменение верстки/программного кода публикуется через коммит в GitHub `main` → Cloudflare Builds. Доступ в `/admin` требует отдельного пароля.

## Публикация

```
npm install
npm run check
npx wrangler deploy
```

Гостевой сайт использует опубликованные анонсы из D1 без тестовых событий и не создаёт ложных броней. До подключения настоящей серверной формы кнопки «Забронировать стол» открывают рабочие `tel:`-ссылки номеров заведений из CMS.

**Перед полноценным запуском:** проверить актуальность телефонов и времени работы, подтвердить оригинальность фотографий, подключить официальный домен. Технический адрес `workers.dev` исключён из индексации; это сделано намеренно. Не обещать онлайн-бронирование без подключённого обработчика и уведомлений.

## Контент и события
- Анонсы с `published=true` появляются в `/events`.
- Будущие сортируются по времени проведения (первый по времени — на главной).
- Прошедшие автоматически оказываются в архиве страницы `/events`.
- Неопубликованные объявления не видны посетителям.
- Время мероприятия вводится в часовом поясе **Минска (UTC+3)**.

## Важное
- Не подключать этот Worker к D1/R2 AVE.
- Секреты не записывать в GitHub и не публиковать в README.
- Изображения и тексты через CMS не требуют правок GitHub.
- Схема таблиц в `migrations/0001_content.sql` (уже применена на отдельной базе NOVA).

## Бронирования / RESERVED

- Для гостей: кнопки «Забронировать стол» отправляют реальные заявки через `POST /api/reservations`, после успешного сохранения в D1 отображается сообщение о получении заявки. Бронь требует подтверждения администратором.
- Для сотрудников: отдельная служебная страница `/reserved`. Сейчас используется действующий пароль редактора NOVA, но авторизация и cookie для служебной страницы отделены от `/admin`.
- Для отдельного пароля: в Cloudflare Workers → `nova-lounge-demo` → Settings → Variables and Secrets добавить секрет `RESERVATIONS_PASSWORD`. Он переопределит общий пароль администратора только для `/reserved`.
- Таблицы: `migrations/0003_reservations.sql` применить к production `nova-content-db` и preview `nova-content-preview-db`.
- Запись: заведение `zyb/pob/east`, дата/время Минска, число гостей, имя, телефон, комментарий, статус и согласие. Статусы меняются в `/reserved`, история изменений записывается в `reservation_audit`.
- Доступ к персональным данным: только после авторизации сотрудников. Не включать их в публичные ответы API, клиентские логи или кэш. Сотрудникам необходима организационная процедура обработки персональных данных и ограничения доступа.
- Telegram ещё не подключён, но в каждой записи уже есть `venue` и `telegram_sent_at`. До интеграции персоналу необходимо проверять `/reserved` вручную.
